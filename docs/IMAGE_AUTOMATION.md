# GPT 세션 이미지 작업 — 계획기 → 생성 → 검사

원소 공방(element-atelier)의 `docs/IMAGE_AUTOMATION.md` 를 삼국지 꼴로 옮긴 것이다(사용자 2026-11-02 「응 1,2,3 다 해줘」 — 유비 · 조운 · 하후돈 · 사마의의 일상컷이 세계 셋에서 같은 장면을 돌려썼다. GPT 세션이 계획기 없이 손으로 짰기 때문).
GPT 세션이 장수 그림을 채우는 길이다. 사람이 지켜보는 세션도 2 · 3절(계획기 → 지시문 묶음 → 검사)은 똑같이 밟는다.
삼국지의 한 장수 = **사는 세계마다**(삼국시대 `samguk` · 중세 판타지 `fantasy` · 메카 `mecha`) 세계 그림 한 장 + 그 세계 그림을 붙인 **일상컷 일곱 장**(`IMAGE_RULES.md` 2절 — 2026-11-11, 전엔 여섯 · 다섯).

## 0. 승인 — 묻지 않고 올린다 (사용자 2026-11-02)

사용자가 원소 공방처럼 정했다(「삼국지도 원소처럼 바로 올리게 바꿔줘」): **GPT 세션은 중간에 묻지 않고, AI 검수(QA) 뒤 바로 올린다. 그림의 시각적 품질은 올라간 뒤 사용자가 본다.**
그래서 GPT 세션에서는 `IMAGE_RULES.md` 1절의 다음 둘이 바뀐다. 사람이 지켜보는 세션은 그대로 「올릴까?」 를 묻는다.

| IMAGE_RULES(1절) | GPT 세션 |
|---|---|
| 올리기 전에 사람이 본다 — 「올릴까?」 | 묻지 않는다. 4절 검수를 적고 올린다 |
| 계획대로 안 나오면(삼국시대가 일본 옷으로, 판타지가 한푸로) 원인을 적어 먼저 묻는다 | 묻지도, 고쳐 다시 그리지도 않는다. 어긋난 데와 원인을 검수 기록에 적고 올린다 |

**세계 그림 → 일상컷 사이는 멈춘다(사용자가 고른다)** — 세계마다 세계 그림 네 장(우리 설계 `<세계>-prompt.txt` 두 장 + GPT 임의 설계 `<세계>-free.txt` 두 장 — 2026-11-09, 의상은 우리 실루엣에서 · 무기는 우리 것, 얼굴 · 머리는 자유)을 뽑아 「우리 설계 1 · 2 / GPT 설계 1 · 2」 로 보이고 묻는다. 사용자가 고른 장만 올리고, 그 장을 붙여 일상컷을 그린다. 고르기 전엔 일상컷으로 넘어가지 않는다 — 화풍이 무엇이든(`IMAGE_RULES.md` 1절, 2026-11-08 「세계컷 생성 후 되묻는거 없이 바로 일상컷으로 가네?」). 위 「묻지 않는다」 는 일상컷과 고른 뒤의 올리기에만 닿는다.

이 승인이 닿지 **않는** 것 — 그 자리에서 멈추고(5절 block) 보고한다: 안전 필터 거절이 `IMAGE_RULES.md` 1절 순서(같은 지시문 한 번 → 노출 한 단계씩 → 계획 바꾸기 한 번)를 다 밟고도 남을 때,
결과가 불분명한 응답, 원본을 잃음, 도구 오류, 다른 세션의 잠금, 받은 그림이 1024×1536 이 아님(한 번 더 — 그래도 아니면 멈춤), 이미 있는 파일 이름.
이미 올라간 그림을 덮거나 지우는 일, 강제 push, 이력 재작성은 어떤 경우에도 하지 않는다.

## 1. 준비

- `AGENTS.md` · `IMAGE_RULES.md` 를 먼저 읽는다. 코드(`sam-atelier`)와 그림 저장소 둘(`sam-atelier-img` · `sam-atelier-img-2`)을 **나란히** 받아 최신 `main` 으로 둔다.
  그림 저장소는 2026-11-12 부터 둘이다(사용자 「원소쪽은 다른 작업중이라 삼국지 먼저 열자.」 — 첫 저장소가 약 1.0 GB 로 찼다, `IMAGE_RULES.md` 3절 「그림 저장소는 여럿이다」):
  **새 그림 · 새 기록은 `sam-atelier-img-2`**, 잠금(`records/automation/claims/`) · 설계 주문(`free/`)은 **`sam-atelier-img` 그대로**. 교체는 그 파일이 있는 저장소(`data/img.json` 의 `where`).
  다른 세션도 같은 저장소에 민다 — push 전에 늘 `git pull --rebase origin main`. 남의 로컬 변경을 reset 하지 않는다.
- Node 와 Python 3 + Pillow 가 있으면 된다. **브라우저는 쓰지 않는다** — 생성기 화면 대신 지시문 묶음(`tools/prompt-pack.cjs`)이 같은 글을 파일로 준다(생성기와 같은 조립부 `lib/prompt-sam.js`).
- 실행 ID 를 **한 번** 정하고 이 실행의 모든 명령에 그대로 쓴다.

```sh
export ATELIER_EXECUTION_ID="sam-$(date -u +%Y%m%dT%H%M%SZ)"
node tools/image-claim.cjs status                      # 잠금 · 다음 차례(읽기만)
```

## 2. 차례와 잠금

```sh
node tools/image-claim.cjs next                         # 다음에 그릴 장수와 빈 자리
node tools/image-claim.cjs claim <장수> --execution $ATELIER_EXECUTION_ID
```

- 차례는 설계표(게임 표) 차례 — **세력 하나를 끝까지 그린 뒤 다음 세력으로**(`IMAGE_RULES.md` 5절). 고르는 것은 도구가 한다. 몫(하루 · 실행마다)은 없다.
- 잠금은 첫 그림 저장소(`sam-atelier-img`) `records/automation/claims/<장수>.json` 하나다(둘째 저장소를 열어도 옮기지 않는다). `claim` 은 그 파일만 커밋해 일반 push 한다 — 다른 세션이 먼저 밀었으면 거절되고 도구가 제 커밋을 되돌린다. 그때는 pull 하고 `status` 부터 다시.
- 잡힌 장수(`working` · `blocked`)는 건드리지 않는다. `blocked` 는 사용자가 정한 뒤 `release --approval '<사용자 말>'` 로만 푼다.
- 한 장수의 빈 자리 = 사는 세계마다 세계 그림 · 일상컷 일곱 장 — 장수 하나 24(2026-11-11 사용자 「그럼 일상컷은 총 7장 되는거야」 — 11-09 여섯 · 21, 전엔 다섯, 기본 화풍 `kr_promo_hikey` — 2026-11-08, 그 앞 `kv_kmmo_23d` · `kv_kmmo_lock` · `kr_mmorpg`, `data/img.json`). 번호는 세계마다 따로, 비어 있는 가장 작은 것부터(`claim` 이 적어 준 `missing` 그대로).
- **자동 설계(`designed: "auto"`) 장수는 그리기 전에 시안**(`IMAGE_RULES.md` 2절 · `AGENTS.md` 3절).

## 3. 계획과 지시문 묶음 — 일상컷은 반드시 계획기로

작업 폴더(`$W`)는 세션 임시 자리에 둔다. **세계 셋을 한 번에** 짠다(세계끼리 장면을 돌려쓰지 않게 — `IMAGE_RULES.md` 2절):

```sh
node tools/casual-plan.cjs <장수> --world all --out $W      # $W/plan-<세계>/plan.json · 기록 · 지시문 — 기록은 옆의 두 그림 저장소 records/<장수> 를 다 읽는다
node tools/prompt-pack.cjs init <장수> --dir $W/pack --plan $W/plan-samguk/plan.json --plan $W/plan-fantasy/plan.json --plan $W/plan-mecha/plan.json
node tools/prompt-pack.cjs build --dir $W/pack                                  # 자리마다 <자리>-prompt.txt(세계 그림에 낸다) · <자리>-gpt.md(일상컷에 낸다) · <자리>-ui.json · INDEX.md
```

- 계획기가 묶음 규칙을 지킨다: 세계마다 일곱 장 중 **정해 둔 세 갈래**(노출 갈래 한 장 — 란제리풍 · 수영복 · 역할극, 세계 안 갈래 한 장 — 방 · 목욕탕 · 지붕 · 여관 · 서재 · 부엌 · 군영 · 정원 · 다리 · 사당 · 숲길 · 나루, 상황 노출 한 장 — 젖은 옷 · 바람 · 반쯤 푼 차림 · 흘러내린 어깨끈, 서로 다른 컷) · **자유 설계 두 장**(옷 자유 · 갈래 자유 — 장면 줄 대신 FREE DESIGN 덩어리, 아래) · 네 시대 · 장소 · 의상 · 자세 · 소품 ·
  **세계 사이 같은 장면 금지**(같은 장소 — 세계 안 `nation_*` 장소는 옷 계열까지 같을 때만 · 같은 자세 추천 = 같은 구도) · 다른 장수 기록에서 덜 쓴 트리 먼저. `--usage none` 은 쓰지 않는다.
- 세계 하나만 남았으면 `--world <세계>` — 다른 세계의 기록은 `--records` 에서 읽어 겹침에 넣는다. 아직 안 올린 다른 계획은 `--others a.json,b.json`.
- 옛 묶음을 두고 **더 그리라는 말이 있을 때만** `--fresh`(그 세계의 가장 큰 번호 뒤로 일곱 장, 옛 묶음과도 겹치지 않게 — 검사는 `--check … --from <첫 번호>`). 빈 자리 채우기엔 쓰지 않는다.
- 계획을 손으로 바꾸지 않는다. `settings.json` 은 **비워 둔 채** build 하는 것이 기본 — 고칠 때만 칸을 채우고 직접 입력(덧붙임 글)엔 `why` 를 적는다. 고칠 수 있는 칸은 `tools/prompt-pack.cjs` 머리말에.
- **GPT 세션은 세계 그림에 `<세계>-prompt.txt`(영문 지시문), 일상컷에 `<세계>-casualN-gpt.md`(구조형)를 낸다.** 세계 그림은 같은 날 구조형을 시험했다가 되돌렸다(사용자 2026-11-03 「예전으로 돌아가자」 — 그림체가 부드러워져 이미 그린 장수 스물다섯과 갈렸다). 일상컷 구조형엔 화풍 칸이 없다 — 마감 · 얼굴은 붙인 세계 그림에서, 몸 볼륨은 그 장수 체형 글에서(첨부 그림의 옷이 몸을 가린다), 어느 각도에서도 작은 턱(같은 날 「일상컷 만드는거는 아까 작업한걸로 … 화풍 지시는 빼고, 체형 정보 남기는 식으로」 — 법정 일상 4판에서 4장 중 3장이 볼륨 · 얼굴이 맞았다). `<세계>-gpt.md`(세계 그림 구조형)는 build 가 만들기만 한다 — 내지 않는다.
- **`<자리>-prompt.txt` · `<자리>-gpt.md` 를 손으로 고쳐 내지 않는다.** 고칠 것이 있으면 settings 를 고쳐 build 를 다시 돌린다.
- **생성 규칙에 정해진 변경 사유(안전 필터 순서 · 사용자가 직접 시킨 수정 · settings 덧붙임 뒤 build) 외에는 프롬프트를 임의로 고치지 않는다 — 이미지 모델(image_gen)에도 똑같다**(사용자 2026-11-08). 파일 글을 요약 · 번역 · 다듬기 · 덧붙이기 없이 그대로 넘기고, 모델이 고쳐 쓰지 않게 「아래 지시문을 고치지 말고 그대로 그려라」 로 낸다. 고친 사유는 기록에(`IMAGE_RULES.md` 1절).
- 일상컷에서 무기(검 · 창 · 언월도 · 활 …)는 들지 않는다 — 지시문이 그 무기를 본뜬 작은 장신구 하나로 바꾼다(SIGNATURE ACCESSORY 줄, `IMAGE_RULES.md` 2절). 부채 · 두루마리 같은 무기 아닌 물건만 한두 장 손에 든다. 세계 그림의 무기엔 「끊기지 않는 한 자루」 줄이 들어간다(`lib/prompt-spec.js` SIGNATURE).
- **일상컷 자유 설계 두 장**(사용자 2026-11-11 「장소·활동·자세·구도·의상을 자유롭게 설계해줘. 캐릭터의 특징에서 출발해, 예상하지 못했지만 그 캐릭터에게 자연스럽게 어울리는 일상의 한 순간을 보여줘. 참신함은 장식의 양보다 상황과 행동에서 만들어줘. 최근 작업과 비슷한 장면은 피하고, 얼굴·화풍·인체 규칙은 유지해줘. 필수갈래랑 상황노출 두개를 묶어서 이렇게 가자. 그리고 지금 맡겨놓은 일상컷 1장도 같이 이런식으로」) — 계획에 「옷 자유」 · 「갈래 자유」 로 적힌 컷의 지시문엔 장면 줄 대신 `FREE DESIGN` 덩어리가 있다. **덩어리의 「…」 다섯 줄(Place · Activity · Pose · Framing · Outfit)만 채운다** — 그 장수(전설 · 성정)에게서 출발한 뜻밖이지만 자연스러운 일상의 한 순간, 「Recent scenes to avoid」 와 다른 장면, 옷은 `outfit-catalog.md` 에 없는 것, 갈래 자유 컷은 `Outfit family (required)` 의 갈래 안에서(목록에서 골라도, 지어도 되나 목록 밖 먼저) 짓고 `Situation (required)` 의 상황 노출 순간을 장면에 담는다(상황은 열려 있다 — 우리 넷이 아닌 것 먼저, 2026-11-11 「상황도 열어주자. 옷도 이제 큰범위로만 지정해줘 …」). 머리 · 최근 장면 · 필수 줄과 덩어리 밖의 줄은 낱말 하나 안 바꾼다. 채운 덩어리는 기록 `generation.free_design`, 넘긴 글 전체는 `free_prompt`. 이것도 「프롬프트 임의 수정 금지」 의 정해 둔 사유다.
- 안전 필터로 한 칸이 끝내 막히면 그 칸만 `--slots N --seed <다른 씨앗>` 으로 계획기에 다시 맡긴다 — 한 번만.

## 4. 그리기와 검수

- `INDEX.md` 의 차례대로, `claim` 의 `missing` 에 있는 자리만 그린다. 자리 하나에 생성 호출 한 번.
- 세계 그림은 **기준 그림 없이** 한 장씩(세계마다 다른 사람). 일상컷은 그 세계 그림을 **꼭** 붙인다(이미지 편집 `images/edits` — 첨부 없이 뽑으면 다른 사람이 된다).
  이 세션에서 받은 원본, 이미 등록된 세계 그림이면 그 파일이 있는 그림 저장소(`where` — 없으면 `sam-atelier-img`)의 `img/<파일>.webp`. 세계 그림이 없는 세계는 일상컷을 그리지 않는다.
- 크기는 1024×1536 — **이미지 도구의 크기 설정으로 세로 1024×1536 을 꼭 지정한다**(글만으로는 가로로 나온 적이 있다). 도구가 실제로 돌려준 파일만 쓴다.
- **검수**(기록의 `qa` — 7절)를 구체적으로: 1024×1536 · 그녀 한 명(말 · 짐승 · 두 번째 인물 없음) · 깃발 · 인장의 한 글자 말고 읽히는 글자 · 로고 · 워터마크 · 틀 ·
  세계 그림이면 고른 세계대로인가(삼국시대가 일본 옷으로, 판타지가 한푸로 가지 않았나) · 일상컷이면 첨부한 세계 그림과 같은 얼굴 · 머리 · 몸인가, 계획 칸(시대 · 장소 · 의상 · 프레이밍 · 자세 · 두 손 · 소품)대로인가 ·
  **일상컷에 무기가 없나(장신구 하나만) · 세계 그림의 무기 · 손에 든 물건이 한 자루로 이어졌나(꺾임 · 잘림 없음 — 몸으로 불가능한 자세도)** · 팔 · 다리 · 손의 수와 이어짐 ·
  **노출이 지정대로인가**(세계 그림은 EXPOSURE 줄, 일상컷은 skin_exposure 줄과 그림을 맞대 본다 — 기록 `qa.exposure`: `match` · `weaker` · `stronger` 와 본 것 한 줄. 사용자 2026-11-08 「gpt세션에서 … 의도적으로 줄이는거 같아」).
- **노출은 세션이 줄이지 않는다.** 지정한 노출 줄을 빼거나 누그러뜨리거나 노출 단계를 미리 낮춰 내지 않는다 — 낮추는 것은 안전 필터가 실제로 막았을 때만, `IMAGE_RULES.md` 1절 순서대로(기록 `generation.retries` 에 막힌 응답). image_gen 에도 지시문 글 그대로(`IMAGE_RULES.md` 1절 「임의 수정 금지」).
- 검수에서 걸린 것은 `passed: false` 와 함께 그대로 적고 **올린다**(0절 — 사용자가 올라간 뒤 본다). 다시 그리지 않는다.
  **다만 아래 다섯 가지는 그 자리만 같은 지시문으로 한 번 다시 그린다**(사용자 2026-11-03 — 같은 지시문도 장마다 갈렸다: 법정 일상 4장 중 1장만 볼륨이 모자랐다):
  얼굴이 길거나 턱이 무거워 보임 · 일상컷 얼굴이 첨부 그림과 다른 사람 · 몸이 체형 글보다 눈에 띄게 마름 · 노출이 지정보다 눈에 띄게 약함(`qa.exposure: weaker` — 2026-11-08) · 팔 · 다리 · 손의 수가 틀림.
  **무기 · 손에 든 물건이 끊기거나 꺾이거나 몸 뒤로 지나가거나 틀 밖으로 잘린 것은 다시 그리지 않는다** — 기록 `qa` 에 적고 그대로 올린다(사용자 2026-11-09 「삼국지 쪽에 무기 잘리는걸로는 이미지 재생성 안하게해줘」 — 전엔 여섯째 다시 그리기 사유였다).
  두 장 다 기록에 남긴다(`generation.redo` — 앞 장의 sha256 과 걸린 항목). 다시 그린 장도 걸리면 나은 쪽을 `passed: false` 로 올린다 — 세 번째는 없다.
  지시문에서 부딪힌 줄(세계 · 장소 · 의상 · 자세 · 프레이밍 · HAND · PROP · 시대)을 찾았으면 원인도 적는다 — 규칙 · 계획기를 고치는 일은 사람이 지켜보는 세션이 한다.
- 올리기 전 `node tools/casual-plan.cjs <장수> --world <세계> --check <새 기록을 넣은 기록 폴더 사본>` 이 세계마다 통과해야 한다(다른 세계와 같은 장면도 본다).

## 5. 멈춤

```sh
node tools/image-claim.cjs block <장수> --execution $ATELIER_EXECUTION_ID --reason '실제 까닭(어느 자리 · 무슨 응답)'
```

- 0절의 「닿지 않는 것」 이면 그 자리는 그리지 않고 block 한다. 그 전까지 검수한 자리는 6절대로 올려도 된다(빈 자리를 줄인다). 거절된 지시문은 sha256 과 함께 `<자리>.blocked.json` 으로 남긴다(지시문 · 시도 수 · 응답 코드).

## 6. 올리기와 끝

1. 자리마다 원본을 WebP(품질 90, method 6, 1024×1536)로 바꾼다. 이름은 `INDEX.md` 의 「올릴 파일」(= `IMAGE_RULES.md` 3절). 같은 이름이 그림 저장소(둘 중 어디든)에 이미 있으면 멈춘다 — 덮지 않는다.
2. 열린 그림 저장소(`sam-atelier-img-2`)에 **한 장수 한 커밋**으로 일반 push: `img/<파일>.webp` 들과 `records/<장수>/` 의 기록 — 세계 그림 `<세계>.<화풍>-ui.json`, 일상컷 `<세계>-casualN.<화풍>-ui.json`, 일상 계획 `<세계>-casual-plan.json`.
   기록에 7절 칸을 더한다. **원본 PNG 는 올리지 않는다** — sha256 만. 썸네일 · `data/img.json` 은 손으로 만들지 않는다(워크플로가 한다).
3. push 가 밀리면 `pull --rebase` 한 번. 그 사이 같은 파일 이름이 들어왔으면 멈추고 보고한다.
4. `썸네일` · `그림 등록` 이 돈 뒤 코드 저장소를 pull 하고 `python3 tools/casual-check.py <장수>` 로 본다. 그리고:

```sh
node tools/image-claim.cjs done <장수> --execution $ATELIER_EXECUTION_ID
```

## 9. GPT 세션이 설계 지시문만 — 그림은 API (2026-11-09)

사용자 「gpt 세션에서도 내 git 읽을 수 있으니까 git에 올려놓고 추론 해달라고 부탁해도 되겠네. 이미지 생성은 api 로 하고」 — GPT 자유 설계(세계 그림 네 장 중 둘)와 일상컷 자유 설계 컷(옷 자유 · 갈래 자유)의 「설계 글」 은 ChatGPT 세션이 쓰고(구독 — API 대화 토큰 0), 그림은 API 생성 탭(`api.html`)이 2.5 로 그린다.

1. 주문 올리기 — `node tools/free-brief.cjs <장수> [--style api25] [--plan <계획 plan.json> …]` 가 첫 그림 저장소(`sam-atelier-img` — 둘째를 열어도 주문 자리는 그대로) `free/<장수>/` 에 `<세계>.<화풍>-brief.txt`(세계마다) · `<세계>-casualN.<화풍>-brief.txt`(계획의 자유 설계 컷마다 — 지시문 + 「FREE DESIGN 덩어리만 채워라」) · `REQUEST.md`(부탁 글), `free/outfit-catalog.md` 를 쓴다. 그림 저장소에서 일반 push.
2. GPT 세션에 `free/<장수>/REQUEST.md` 를 그대로 붙여 넣는다 — 세션은 주문을 읽고 **그림 없이** 지시문 글만 `<세계>.<화풍>-gpt1.txt` · `-gpt2.txt`(서로 다르게) · `<세계>-casualN.<화풍>-gpt1.txt`(자유 설계 덩어리의 「…」 다섯 줄만 채운 지시문 전체)로 같은 폴더에 올린다. 「fixed」 칸(실루엣 목록 · 무기 · 색 · 노출 · 얼굴 비율 · 구도)은 그대로, 이미 있는 `-gpt*.txt` 는 덮지 않는다.
3. API 프롬프트 탭에서 그 자리를 「GPT 자유 설계로 보내기」(일상컷은 자유 설계 컷 체크 — 갈래 자유면 갈래 · 상황도) → API 생성 탭의 「GPT 세션이 쓴 지시문」 에서 「git 에서 N번 불러오기」(Pages 가 돈 뒤) 또는 붙여 넣기 → 「그리기」. 대화 모델은 부르지 않는다. 기록 `generation` 에 `chat_model: gpt-session` · `free_source`(git 경로 또는 pasted) · `free_prompt`(그 글).
